# uaRO Pad 0.4 — языки, вкладка настроек, Mouse Freedom 2, окно

Дополняет `2026-10-12-uaro-pad-settings-menu-design.md` (0.3). Утверждено пользователем:
- языки меню: английский (по умолчанию), украинский, русский, переключение строкой в меню Start;
- мышь: точный курсор, клики и колесо только над игрой, курсор Windows над рамкой окна, курсор не выходит
  из окна (опция);
- дополнительно: клик для перехода в окно не уходит в игру, процессор в фоне, окно без рамки, боковые кнопки
  мыши → F1–F9;
- исправление выбора цели для A и слотов («бьёт не ближайшего»).

Правый стик для камеры, подсветка следующей цели и радиус ходьбы в настройках — версия 0.5, своя спецификация.

## 1. Языки

- `[general] language = en | uk | ru` в `uaro-pad.ini`, по умолчанию и при неизвестном значении — `en`.
- Переводится всё, что видит игрок: меню Start (заголовок, вкладки, строки, действия, значения настроек,
  подсказка, «Сохранить» / «Отмена»), README (`README.md` — английский, `README.uk.md`, `README.ru.md`),
  комментарии в поставляемом `uaro-pad.ini` (английские).
- Шапка `uaro-pad-binds.ini` — английская, только ASCII: в файле остаётся одна кодировка (имена персонажей
  в кодировке системы).
- Лог остаётся английским. Скиллы в меню — как их называет клиент (`AC_DOUBLE`), предметы — как их пишет
  клиент.

## 2. Меню: две вкладки

- В шапке панели две вкладки: «Кнопки» и «Настройки». LB / RB или клик по вкладке переключают их. Высота
  панели одна для обеих вкладок (по большей), панель не прыгает.
- «Кнопки» — как в 0.3: 14 кнопок и «Вернуть всё по умолчанию».
- «Настройки» — строки со значениями, которые листаются ←→ / ◄ ►, как действия кнопок:

  | Строка | Значения | Ключ в `uaro-pad.ini` |
  |---|---|---|
  | Язык | English / Українська / Русский (каждый на своём языке) | `[general] language` |
  | Курсор не выходит из окна | выкл / вкл | `[mouse] lock` |
  | Клик, который делает окно активным | не идёт в игру / идёт в игру | `[mouse] focus_click` |
  | Средняя кнопка мыши | — / F1…F9 | `[mouse] middle` |
  | Кнопка мыши 4 | — / F1…F9 | `[mouse] button4` |
  | Кнопка мыши 5 | — / F1…F9 | `[mouse] button5` |
  | Окно без рамки | выкл / вкл | `[window] borderless` |
  | Экономить процессор в фоне | выкл / вкл | `[window] background_sleep_ms` |
  | Вибрация | выкл / вкл | `[rumble] enabled` |
  | «!» над целью | выкл / вкл | `[aim] mark` |
  | Сбросить все настройки | — | — |

- Управление то же, что в 0.3: ↑↓ — строка, ←→ — значение, Y — значение по умолчанию для строки, A или
  Start — сохранить и закрыть (на последней строке A сбрасывает вкладку, меню остаётся открытым), B — закрыть
  без сохранения.
- «По умолчанию» (Y и «Сбросить все настройки») — встроенные значения: из разделов 4–5, вибрация и «!» —
  вкл, язык — `en`; а не то, что было в файле.
- Язык меняется в открытом меню сразу; остальные настройки начинают действовать после «Сохранить». «Отмена»
  и потеря фокуса окном игры ничего не сохраняют и возвращают прежний язык.
- «Экономить процессор» во включённом виде пишет в файл значение, которое там было (если оно не 0), иначе 10.

## 3. Запись `uaro-pad.ini`

- Модуль впервые пишет `uaro-pad.ini`, и только по «Сохранить» и только изменённые в меню ключи.
- Файл перед записью читается заново (его могли поправить руками или сохранить из второго клиента).
- Ключ есть в своей секции — заменяется только значение, комментарий в строке и всё остальное в файле
  остаются байт в байт. Ключа нет — дописывается в конец своей секции. Секции нет — дописывается в конец файла.
  Перевод строк берётся из файла (CRLF или LF).
- Запись атомарная, как у `uaro-pad-binds.ini`: временный файл и замена. Не получилось — вибрация «отказ»,
  настройки действуют до закрытия клиента.

## 4. Mouse Freedom

### 4.1. Точный курсор
- Если сборка клиента та, что у uaRO (проверка байтов кода, как у панели хоткеев), модуль на каждом опросе мыши
  читает позицию курсора клиента (`g_mouse` 0x6ee6f0: x +0x14, y +0x18) и разрешение игры (0x6ebe1c,
  0x6ebe20) и отдаёт клиенту `lX = цель − x`, `lY = цель − y`. Цель — курсор Windows (или точка ходьбы стиком)
  в координатах клиентской области, пересчитанная в разрешение игры (ширина и высота области → ширина и высота
  игры), в пределах `[0, w−1] × [0, h−1]`.
- Рывка в угол (кадр «settling») больше нет: ни при запуске, ни при смене размера, ни при возврате фокуса.
- Разрешение игры вне 1…8192 или чтение не удалось — этот опрос идёт по-старому (оценка позиции, 0.3).
- Неизвестная сборка — всё как в 0.3.

### 4.2. Клики и колесо — только над игрой
- «Над игрой» — курсор Windows в клиентской области окна игры, и `WindowFromPoint` возвращает само окно игры
  (не окно поверх неё, не меню модуля).
- Не над игрой: колесо (`lZ`) обнуляется; кнопка, нажатая там, скрыта от клиента до отпускания. Кнопка,
  зажатая над игрой (перетаскивание), доходит до клиента до отпускания, куда бы курсор ни ушёл.
- Виртуальная кнопка ходьбы стиком под это правило не попадает.

### 4.3. Курсор Windows над рамкой окна
- Клиент в оконном режиме на любой `WM_SETCURSOR` делает `SetCursor(NULL)` — курсор Windows не виден и над
  заголовком, и над краями. Модуль подменяет оконную процедуру игры (один раз, когда узнаёт окно):
  `WM_SETCURSOR` с hit-test, отличным от `HTCLIENT`, уходит в `DefWindowProc` (стрелка, курсоры изменения
  размера); остальное — в процедуру клиента.

### 4.4. Курсор не выходит из окна — `[mouse] lock = 0 | 1`, по умолчанию 0
- Пока окно игры на переднем плане и не свёрнуто, курсор заперт в клиентской области (`ClipCursor`); каждый
  тик модуль проверяет, что система не сняла ограничение, и ставит его снова.
- Окно ушло с переднего плана (Alt+Tab, Win, клик по другому окну), свёрнуто, модуль отключился из-за ошибки
  или клиент закрывается — ограничение снимается.

### 4.5. Клик, который делает окно активным — `[mouse] focus_click = 0 | 1`, по умолчанию 0
- 0: окно игры стало активным, а кнопка мыши в этот момент зажата (это клик, которым на окно переключились) —
  кнопка скрыта от клиента до отпускания. 1 — как в 0.3.

### 4.6. Боковые кнопки мыши → F1–F9
- `[mouse] middle`, `button4`, `button5` = `none` | `F1` … `F9`, по умолчанию `none`. Клиент сам читает только
  левую и правую кнопки, эти три ему не нужны.
- Пока окно игры на переднем плане, меню закрыто и курсор над игрой: нажатие кнопки — клавиша нажата
  (`SendInput`, скан-код и VK), отпускание — отпущена. Клиент получает обычное нажатие F-клавиши: скилл
  целится мышью, как с клавиатуры. Автоповтора нет.
- Окно ушло с переднего плана, пока кнопка зажата, — клавиша отпускается сразу.

## 5. Окно

### 5.1. Без рамки — `[window] borderless = 0 | 1` (по умолчанию 0), `[window] position = center | keep | X,Y`
  (по умолчанию `center`)
- Только в оконном режиме (у окна есть заголовок). Модуль убирает заголовок и края (`WS_POPUP`), размер
  клиентской области не меняется. `center` — по центру монитора, на котором окно (если окно больше монитора —
  в его левый верхний угол); `keep` — картинка остаётся на месте; `X,Y` — левый верхний угол картинки на
  экране.
- Применяется, когда модуль узнаёт окно игры, и по «Сохранить» в меню. Выключение в меню возвращает прежний
  стиль и положение окна.
- Разрешение игры модуль не меняет: оно задаётся настройками клиента.

### 5.2. Процессор в фоне — `[window] background_sleep_ms = 0…100`, по умолчанию 10 (0 — выкл)
- Когда очередь сообщений клиента пуста (`PeekMessageA` вернул FALSE), а окно игры не на переднем плане или
  свёрнуто, модуль засыпает на столько миллисекунд. Игра в фоне продолжает получать данные сервера
  (около 100 кадров в секунду при 10 мс).

## 6. Выбор цели

Жалоба: A и X выбирают не ближайшего монстра, а будто «первого в списке», и бегут к нему мимо ближних.
Причины в модуле (уточнено после ревью):
- A держит живую цель, как бы далеко от неё ни ушёл игрок.
- Сервер показывает клиенту монстров на 35 клеток вокруг (`conf/battle/client.conf`: `area_size: 35`), то есть
  далеко за краем экрана, и «ближайшим» мог стать невидимый на экране монстр.
- «Ближайший» — по клеткам RO (Чебышёв), при равенстве — меньший id, то есть появившийся раньше.
- Первоначальная версия этого раздела называла причиной неразобранный `0x007b`. Это неверно: при PACKETVER 7
  uAthena шлёт идущих не-игроков пакетом `0x022c` (ветка не-PC в `clif_set007b`), который модуль разбирает
  с 0.1. Разбор `0x007b` оставлен — он верен для старых версий протокола и ничего не стоит.

Исправления:
- Кандидаты в цели — только в пределах 15 клеток (Чебышёв, как дальность выбора правым стиком): примерно
  край экрана.
- Ближайший — по прямой (квадрат расстояния по клеткам), при равенстве — по Чебышёву, затем по id.
- Цель дальше 15 клеток сбрасывается сама: заметка в лог, атака прекращается; зажатая A берёт следующую
  ближайшую, как после смерти цели. Охотник, отбегающий на 9 клеток и стреляющий, цель не теряет.

## 7. Изменения в коде

- `core/i18n` (новый): `Lang { En, Uk, Ru }`, разбор и запись токена, `tr(Lang, Text)` — все строки меню на
  трёх языках; подписи действий (`actionLabel`) и строка «Слот F3, ряд 2» берут язык.
- `core/config/config`: новые поля и ключи; `core/config/ini_edit` (новый) — замена значений ключей в тексте
  ini с сохранением всего остального.
- `core/config/settings` (новый): `Settings` — то, что правит вкладка «Настройки», чтение из `Config`, строки
  и значения для меню, следующее значение, ключи и значения для записи в файл.
- `core/logic/settings_menu`: вкладки, строки настроек, LB / RB, сброс вкладки; при сохранении — раскладка и
  настройки.
- `core/logic/cursor_bridge`: точный режим (цель в координатах игры минус курсор клиента).
- `core/proto/s2c_parser`: `0x007b` (для старых версий протокола); `core/logic/targeting`: кандидаты в пределах
  15 клеток, ближайший по прямой; `core/logic/controller`: сброс цели дальше 15 клеток.
- `core/logic/mouse_gate` (новый): кнопки и колесо только над игрой, клик активации, боковые кнопки → события
  клавиш, решение «спать ли в фоне». Без Windows, с тестами.
- `win/client_mouse` (новый): проверка сборки, чтение курсора и разрешения клиента.
- `win/game_window` (новый): подмена оконной процедуры (`WM_SETCURSOR`), окно без рамки и возврат,
  `ClipCursor`, `SendInput` клавиш.
- `win/hooks`: `PeekMessageA` — сон в фоне.
- `win/runtime`: всё это вместе, запись `uaro-pad.ini`, применение настроек по «Сохранить»; `win/overlay`:
  вкладки, строки настроек, тексты из `View`.
- Версия `0.4.0`.

## 8. Тесты

- i18n: у каждого текста три непустых перевода; токены языков; подписи действий на трёх языках.
- config: новые ключи, значения по умолчанию, неверные значения.
- ini_edit: замена значения с сохранением комментария; добавление ключа в секцию; добавление секции; CRLF;
  нетронутые строки байт в байт; файл с BOM и кириллицей в комментариях.
- settings: чтение из `Config`, листание значений (язык, F-клавиши, «процессор» со своим числом из файла),
  сброс, ключи для записи.
- settings_menu: LB / RB и клик по вкладке, листание настроек, сброс строки и вкладки, Save отдаёт раскладку
  и настройки, Cancel — прежние.
- cursor_bridge: точный режим — пересчёт разрешения, пределы, `dx = цель − курсор`, без кадра «settling».
- mouse_gate: колесо вне игры, нажатие вне игры скрыто до отпускания, перетаскивание наружу, клик активации,
  боковые кнопки (нажатие, отпускание, потеря фокуса), сон в фоне.
- выбор цели: `0x007b` даёт идущего монстра; монстр дальше 15 клеток не кандидат (зажатая A не дёргается);
  ближайший по прямой, а не по Чебышёву; цель дальше 15 клеток сбрасывается, зажатая A переходит к ближайшей;
  цель на 9 клетках остаётся.
- Windows-часть (вкладки на панели, курсор над рамкой, `ClipCursor`, рамка окна, `SendInput`) проверяет
  пользователь; список проверок — в сообщении к сборке.

## 9. Вне 0.4

- Правый стик: R3 переключает «цель» ↔ «камера» (поворот и зум, угол камеры из памяти клиента), сброс цели —
  на L3; значок над монстром, которого ударит A, потом постоянная метка; радиус ходьбы строкой в настройках —
  всё это 0.5.

- Бесконечный поворот камеры: клиент крутит камеру движением курсора и останавливается у края экрана и без
  модуля.
- Боковые кнопки — только F1–F9 (не слоты рядов 2–3 и не действия геймпада).
- Модуль не меняет разрешение игры.
