# uaRO Pad 0.3 — меню настроек кнопок по Start

Дополняет `2026-10-12-uaro-pad-v2-hunter-design.md`. Утверждено пользователем: окно поверх игры, своя раскладка
у каждого персонажа («давай посмотрим что получится»).

## 1. Что видит игрок

- **Start** открывает панель «uaRO Pad — <имя персонажа>» поверх окна клиента и закрывает её. Игра не
  закрывается и не перезапускается; сохранённая раскладка действует сразу.
- Пока панель открыта, геймпад управляет меню, персонаж стоит (ходьба стиком останавливается обычным «стопом»),
  клики мышью по игре не проходят. Окно игры остаётся активным: панель не забирает фокус.
- Строки — 14 кнопок: A, B, X, Y, LB, RB, LT, RT, D-pad ↑ → ↓ ←, L3, R3; последняя строка — «Вернуть всё по
  умолчанию». Start, Back и оба стика закреплены.
- Действие кнопки: «—» (ничего), «Атака», «Слот F1…F9» любого из трёх рядов панели (27 слотов), «Подобрать»,
  «Сесть / встать», «Сбросить цель». Для слота рядом видно, что в нём лежит (скилл или предмет из панели клиента).
- Управление: ↑↓ или левый стик — выбрать строку; ←→ — сменить действие; зажатые стрелки листают с
  повтором (через 350 мс, затем каждые 120 мс); список строк и действий закольцован. A — сохранить и
  закрыть (на последней строке — вернуть всё по умолчанию, меню остаётся открытым); Y — вернуть по умолчанию
  выбранную кнопку; B — закрыть без сохранения; Start — сохранить и закрыть.
- Мышь: клик по строке выбирает её, клик по ◀/▶ меняет действие, кнопки «Сохранить» и «Отмена» внизу.
- Нажатие, которым панель открыли или закрыли, в игру не уходит (кнопки, зажатые при закрытии, не считаются
  новым нажатием).
- Если окно игры теряет фокус, панель закрывается без сохранения.

## 2. Персонажи и файл

- Персонаж определяется по char id из 0x009b (смещение 9). Имя — ответом сервера на запрос имени своего
  аккаунта (C→S 0x008c, S→C 0x0095 / 0x0195, имя со смещения 6), один раз за подключение к карт-серверу.
- Раскладки — в `uaro-pad-binds.ini` рядом с клиентом (пишет модуль; `uaro-pad.ini` не трогается):

  ```
  [default]
  A = attack
  X = slot 1
  [char 150001]
  name = Hunter
  A = attack
  ```
  Кнопки: `A B X Y LB RB LT RT UP RIGHT DOWN LEFT L3 R3`; действия: `none`, `attack`, `slot N` (1–27),
  `pickup`, `sit`, `untarget`. Чего нет в секции персонажа — берётся из `[default]`, чего нет там — из
  встроенной раскладки 0.2. Неизвестные ключи и значения пропускаются.
- Новый персонаж получает `[default]`. До входа на карту (персонаж не известен) меню правит `[default]`.
- Запись атомарная: временный файл и замена.

## 3. Изменения в коде

- `config/bindings` (новый): `Action{kind, slot}`, `kBindableButtons`, `Bindings`, `defaultBindings()`,
  `nextAction()`, подписи для меню, `Profiles` + `parseProfiles` / `formatProfiles`.
- `logic/controller`: таблица кнопок берётся из `Bindings` (`setBindings`); `ViewInfo::paused` — меню открыто:
  остановить ходьбу, ничего не делать, но помнить зажатые кнопки.
- `logic/settings_menu` (новый): модель меню без Windows — выбор, смена действий, повтор, сохранение/отмена,
  строки для отрисовки.
- `world`: панель клиента — все 27 слотов (`kClientBarSlots = 27`), доступ к прочитанным слотам для подписей.
- `proto`: char id из 0x009b; S→C 0x0095 / 0x0195 → `EvActorName`.
- `session`: профили, текущий персонаж и его имя, запрос своего имени, `saveBindings`.
- `win/overlay` (новый): окно меню (GDI, без активации, поверх окна игры), мышь; `win/client_bar`: 27 слотов,
  имена в UTF-8 для подписей; `win/runtime`: Start, меню, глушение кнопок мыши, чтение/запись файла.
