# uaRO Pad — поддержка геймпада для легаси-клиента uaRO

Дата: 2026-10-12 · Статус: черновик на ревью

## 1. Цель

Играть на сервере uaRO в легаси-клиенте `uaRO-1.1.exe` с Xbox-геймпадом: ходить стиком, применять скиллы и предметы
с кнопок, атаковать с автовыбором монстра. Клавиатура и мышь продолжают работать (гибридная игра).
Сейчас — для себя; архитектура не должна мешать позже раздавать модуль игрокам через патчер.

**Критерии успеха v1**
- Ставится копированием двух файлов в папку клиента (`dinput.dll`, `uaro-pad.ini`), удаляется их удалением; exe не меняется.
- Без геймпада и при любой ошибке модуля клиент работает как обычно.
- Можно пройти локацию и убить монстров, не трогая мышь: ходьба стиком, атака, скиллы из слотов, подбор.

## 2. Исходные факты (проверено 2026-10-12)

**Клиент** — `/root/uar/uAthena/exe.zip` → `uaRO-1.1.exe`: PE32 i386, Sakexe 2007, packet_ver 22.
- Из `DINPUT.dll` импортирует только `DirectInputCreateA`.
- `USER32`: `GetCursorPos`, `ScreenToClient`, `GetAsyncKeyState`, `GetKeyState`, `PeekMessageA` и др.
- `WS2_32` по ординалам: `recv` (16), `send` (19), `select` (18), `ioctlsocket` (10) и др., плюс `WSASend` по имени.
- Упоминаний joystick/XInput нет — своей поддержки геймпада у клиента нет.

**Сервер** — uAthena, `/root/uar/uAthena`.
- Шифрования и обфускации пакетов нет.
- Длины пакетов и раскладки C→S для v22 — `db/packet_db.txt`; форматы S→C — `src/map/clif.c` (`PACKETVER 7`).
- Нужные пакеты C→S (v22):

  | Действие | Пакет | Длина | Поля (смещения) |
  |---|---|---|---|
  | Шаг | `0x00a7` walktoxy | 8 | pos3 @5 |
  | Атака / сесть / встать | `0x0190` actionrequest | 19 | target @5, type @18 (7 — атака, 2 — сесть, 3 — встать) |
  | Скилл по цели | `0x0072` useskilltoid | 25 | lv @6, skill @10, target @21 |
  | Скилл в клетку | `0x0113` useskilltopos | 22 | lv @5, skill @9, x @12, y @20 |
  | Подобрать | `0x00f5` takeitem | 8 | floor id @4 |
  | Использовать предмет | `0x009f` useitem | 14 | index @4, account id @10 |

- При входе на карту сервер присылает панель горячих клавиш `0x02b9`: 27 слотов × {тип: 0 — предмет, 1 — скилл; id; lv}
  (`clif_hotkeys_send`). Изменения клиент отправляет пакетом `0x02ba`.
- При атаке сервер сам ведёт персонажа к цели (`unit_attack`). При скилле вне дистанции сервер отказывает (`unit.c`),
  при подборе требует ≤ 2 клеток (`pc_takeitem`) — подход в этих случаях делает модуль.

## 3. Раскладка v1 (утверждена)

| Кнопка | Действие |
|---|---|
| Левый стик | Ходьба в сторону наклона: вверх на стике — вверх на экране, даже если камера повёрнута. Отпустили — персонаж останавливается. |
| A | Атаковать текущую цель; нет цели — ближайшего монстра. |
| D-pad → / ← | Перевести атаку на следующего / предыдущего монстра по удалённости. |
| X | Автоатака вкл/выкл: когда цель умирает, сразу берётся следующая ближайшая. |
| B | Подобрать ближайший предмет на земле. |
| Y | Сесть / встать. |
| Зажатый LT / RT / LB / RB + A/B/X/Y | 16 слотов панели: LT — F1–F4 первого ряда, RT — F5–F8 первого ряда, LB и RB — то же для второго ряда. Внутри группы A, B, X, Y — 1-й…4-й слот. |
| Back | Включить / выключить модуль. |

Свободны в v1: правый стик, D-pad ↑/↓, Start, L3, R3.

## 4. Архитектура

Один модуль `dinput.dll` (32 бита, C++17, статическая линковка), который клиент загружает вместо системного.
Внутри два слоя:

```
┌──────────────── win/  (только Windows) ─────────────────┐
│ dinput_proxy — экспорт DirectInputCreateA, обёртки COM  │
│ iat_hooks    — патч таблицы импорта exe                 │
│ net_hooks    — recv / send / WSASend, своя отправка     │
│ input_hooks  — GetCursorPos, мышь DirectInput           │
│ xinput_pad   — опрос XInput, вибрация                   │
│ log, чтение ini, проверка фокуса окна                   │
└─────────────┬────────────────────────────▲──────────────┘
              │ байты пакетов, PadState,   │ исходящие пакеты,
              │ время, размер окна, фокус  │ VirtualMouse, Rumble
┌─────────────▼────────────────────────────┴──────────────┐
│ core/  (переносимый C++, без <windows.h>, тесты на Linux)│
│ proto  — таблица длин v22, нарезка потока, разбор/сборка│
│ world  — WorldState: я, акторы, предметы на земле,      │
│          инвентарь, скиллы, панель горячих клавиш       │
│ logic  — Controller: кнопки → намерения → действия      │
│ config — разбор uaro-pad.ini                            │
└─────────────────────────────────────────────────────────┘
```

**Поток данных** — всё в игровом потоке клиента:
1. Клиент читает данные сервера → хук `recv` отдаёт их клиенту без изменений, а копию — в `core::proto` →
   события → `WorldState`.
2. Каждый кадр клиент опрашивает мышь DirectInput → это наш тик: опрос XInput → `Controller::tick(pad, world, now)` →
   решения:
   - виртуальная мышь (позиция + ЛКМ) — применяется в этом же опросе и в ответах `GetCursorPos`;
   - исходящие пакеты — в очередь, отправляются настоящим `send` в сокет карт-сервера на границе пакетов клиента.
   Запасной источник тика — `PeekMessageA`, если мышь DirectInput не опрашивается.
3. Хуки `send`/`WSASend` видят пакеты клиента: из `0x009b` (wanttoconnection) берём свой account ID и опознаём сокет
   карт-сервера, из `0x02ba` — изменения панели; заодно отслеживаем границы исходящих пакетов.

**Принципы**
- `core` ничего не знает о Windows → вся логика тестируется на Linux.
- Разбирается только сокет карт-сервера (тот, что отправил `0x009b`). Трафик логин- и чар-сервера (там пароль)
  не разбирается и не логируется.
- Входящий поток не меняется: клиент получает ровно то, что прислал сервер.

## 5. Перехват

- **Прокси `dinput.dll`.** Экспортирует `DirectInputCreateA`; остальные экспорты системной dinput — транзитом.
  Системная `dinput.dll` грузится из системной папки при первом вызове (не в `DllMain`). Обёртки над
  `IDirectInput*A` и `IDirectInputDevice*A` (включая полученные через `QueryInterface`) для мыши и клавиатуры,
  остальное — транзит. HWND игры берётся из `SetCooperativeLevel`.
- **IAT-хуки** ставятся при первом `DirectInputCreateA`: `GetCursorPos`, `recv`, `send`, `WSASend`, `PeekMessageA`.
- **Виртуальная мышь.** Пока она активна, `GetCursorPos` возвращает её позицию, а состояние кнопок мыши DirectInput
  (`GetDeviceState` / `GetDeviceData`) — её ЛКМ. Неактивна — всё транзитом, настоящая мышь работает.
- **Диагностика M0.** Логируется, каким путём клиент реально читает мышь (immediate или buffered DirectInput,
  `GetCursorPos`). M1 реализует подтверждённый путь.

## 6. Модель мира (пакеты S→C)

| Что | Пакеты |
|---|---|
| Я: позиция, карта | `0x0073` (вход), `0x0091` / `0x0092` (смена карты / сервера), `0x0087` (свой шаг), `0x0088` (поправка), `0x01ff` (отброс) |
| Акторы | `0x0078` `0x0079` `0x007b` `0x007c`, `0x01d8`–`0x01da`, `0x022a`–`0x022c`, `0x0086` (движение), `0x0080` (исчез; тип 1 — умер), `0x01a4` (свой питомец) |
| Бой | `0x008a` (удар; типы 2/3 — сел/встал), `0x01de` `0x0114` `0x011a` (скиллы), `0x0110` (скилл не удался) |
| Предметы на земле | `0x009d`, `0x009e`, `0x00a1` |
| Инвентарь | `0x01ee` / `0x00a3`, `0x00a4`, `0x00a0`, `0x00af`, `0x01c8` / `0x00a8` |
| Скиллы | `0x010f` (список: id, inf, lv, range), `0x010e`, `0x0147` |
| Панель | `0x02b9` (и исходящий `0x02ba`) |

Точные смещения берутся из `clif.c` при реализации и закрепляются тестами с hex-фикстурами.

- Монстр — актор с классом 1001–3999, кроме своего питомца. Чужой питомец неотличим от монстра — его отсекает таймаут
  атаки (раздел 7).
- Позиция идущего актора интерполируется по начальной и конечной клетке, скорости и времени.
- Смена карты очищает акторов и предметы на земле.

## 7. Логика

**Ходьба.** Стик за мёртвой зоной → виртуальный курсор в точке `центр окна + направление × радиус`
(по умолчанию 0.22 от меньшей стороны окна) и зажатая ЛКМ — дальше клиент ведёт персонажа сам. Отпустили стик →
ЛКМ отпускается и отправляется шаг на текущую клетку (остановка). Пока стик наклонён, автоатака на паузе.

Риск: в точке ходьбы окажется монстр, НПЦ, предмет или окно интерфейса — тогда клиент атакует или заговорит вместо шага.
Механизм выбирается в M1 по факту:
- (а) нажимать ЛКМ в центре экрана (на себе) и потом уводить курсор наружу;
- (б) в хуке `send` заменять случайные атаку / разговор / подбор, вызванные виртуальной мышью, на шаг к той же клетке;
- (в) запасной путь — шаги пакетами `walktoxy`; направление экрана → карты калибруется по шагам, которые клиент
  отправил в ответ на виртуальную мышь (так учитывается поворот камеры).

**Автоцель**
- Кандидаты — живые монстры в зоне видимости, не в чёрном списке. Порядок — по расстоянию (по большей из разниц
  координат, как считает сервер), при равенстве — по ID.
- A: есть живая цель — атаковать её, нет — ближайшую. D-pad → / ← — следующая / предыдущая в этом порядке;
  если цели нет, обе берут ближайшую.
- Отказ: если за `give_up_seconds` (4 с) нет ни одного нашего удара или скилла по цели (`0x008a`, `0x01de`, `0x0114`
  от меня по ней; промах тоже считается) — цель уходит в чёрный список на `blacklist_seconds` (10 с),
  при автоатаке берётся следующая.
- Цель умерла или исчезла → сброс; при автоатаке — следующая ближайшая.
- Автоатака работает, пока персонаж не сидит и стик в покое.

**Модификаторы.** Пока зажат LT, RT, LB или RB, лицевые кнопки работают только как слоты. Триггер считается зажатым
при наклоне больше 50 %. Если зажато несколько модификаторов, действует тот, что нажат первым.

**Слоты.** Кнопка → номер слота (LT: 0–3, RT: 4–7, LB: 9–12, RB: 13–16) → содержимое из `0x02b9`:
- предмет → индекс в инвентаре по item ID → `useitem`; предмета нет — тик вибрации «нельзя»;
- скилл → уровень `min(уровень в слоте, изученный)`; поле `inf` из `0x010f` (битовая маска) проверяется в порядке:
  - 2 (земля) → клетка цели; для списка `ground_self` и при отсутствии цели — своя клетка;
  - 1 (враг) → текущая цель, нет — ближайший монстр;
  - 4 или 16 (на себя / поддержка) → свой ID;
  - 0 (пассивный) → ничего, тик «нельзя»;
- если цель дальше дистанции скилла (`range` из `0x010f`) — подход шагами `walktoxy`, затем каст.

**Подбор (B).** Ближайший предмет на земле в пределах 10 клеток. Дальше 1 клетки — подход шагами, затем `takeitem`.

**Подход** (для скиллов и подбора): шаг `walktoxy` к текущей клетке цели раз в 250 мс, пока она не окажется
в нужной дистанции. Отменяется, если тронут стик, цель пропала или прошло 5 с.

**Сесть / встать (Y)** — по текущему состоянию (из `0x008a`) → `actionrequest` с типом 2 или 3.

**Back** — вкл/выкл модуля. Выключенный модуль продолжает следить за миром, но ничего не делает.

**Фокус.** Действия и виртуальная мышь — только когда окно клиента на переднем плане (`GetForegroundWindow`).
С несколькими клиентами геймпад управляет активным.

**Вибрация.** Смена цели — короткий импульс; автоатака вкл — два коротких, выкл — один длинный; действие невозможно —
слабый тик. Отключается в ini.

## 8. Конфиг и логи

`uaro-pad.ini` рядом с exe; нет файла или ключа — значения по умолчанию.

```ini
[general]
enabled = 1
log_level = info        ; error | info | debug

[stick]
deadzone = 0.25
walk_radius = 0.22      ; доля меньшей стороны окна

[target]
give_up_seconds = 4
blacklist_seconds = 10
attack_interval_ms = 300

[skills]
ground_self = 12,25,27,70   ; Safety Wall, Pneuma, Warp Portal, Sanctuary — ставить под себя

[rumble]
enabled = 1
```

`uaro-pad.log` рядом с exe, перезаписывается при каждом запуске.
- Трафик логин- и чар-сервера не пишется никогда; `0x009b` — без ключей сессии.
- Hex-дампы пакетов карт-сервера — только при `log_level = debug`.

## 9. Ошибки и безопасность

- **Fail-open.** Любое исключение или ошибка в коде модуля ловится на границе хука → модуль переходит в режим
  «только транзит» до перезапуска клиента и пишет причину в лог. Клиент продолжает работать.
- **Рассинхрон потока** (неизвестный ID пакета, невозможная длина) → разбор этого соединения выключается, действия
  пакетами недоступны до следующего подключения к карт-серверу (новый сокет после перезахода или смены сервера);
  ходьба виртуальной мышью продолжает работать.
- **Своя отправка** — только из игрового потока, на границе исходящих пакетов клиента и только когда сокет готов к записи.
  Если `send` принял пакет не целиком, остаток дописывается сразу, до возврата управления клиенту.
- **Потоки.** Хук, вызванный не из игрового потока, работает транзитом.
- **Темп.** Атака — не чаще `attack_interval_ms`; скилл или предмет — не чаще раза в 150 мс; шаги подхода — не чаще
  раза в 250 мс.
- **Нет XInput / геймпад отключён** → модуль молчит, клиент работает; подключение геймпада подхватывается на лету.

## 10. Тестирование

- **Юнит-тесты на Linux** (host GCC, CTest, маленький самописный раннер без внешних зависимостей):
  - таблица длин v22 — сверка с `packet_db.txt`;
  - нарезка потока: пакеты, порванные и склеенные в разных местах;
  - каждый разборщик S→C и сборщик C→S — hex-фикстуры по раскладкам из `clif.c` / `packet_db.txt`;
  - `WorldState`: вход, смена карты, появление / движение / смерть, инвентарь, скиллы, панель;
  - логика: выбор, перебор и отказ от цели, автоатака, слоты по типам, подход, подбор, сесть / встать,
    мёртвая зона и радиус ходьбы, фокус, вкл/выкл.
- **Проверка сборки:** кросс-сборка MinGW i686 и скрипт, который через `objdump` проверяет экспорт `DirectInputCreateA`
  и отсутствие зависимостей, кроме системных DLL.
- **Ручная проверка на Windows** (пользователь), по этапам:
  - **M0** — клиент с модулем запускается и играется как раньше; в логе: геймпад найден, каким путём клиент читает мышь,
    вход на карту и свой ID.
  - **M1** — ходьба стиком и остановка; выбор механизма ходьбы из раздела 7.
  - **M2** — A, D-pad, X, отказ от недостижимой цели.
  - **M3** — слоты: скилл по врагу (в том числе с подходом), бафф на себя, наземный скилл, предмет.
  - **M4** — B, Y, Back, вибрация, два клиента одновременно.
- По желанию — запись потока карт-сервера в debug-режиме для новых фикстур.

## 11. Сборка и поставка

- Репозиторий `/root/uaro-gamepad`, CMake. Кросс-тулчейн `i686-w64-mingw32` (GCC 12.2, уже установлен);
  тесты — host GCC 14.2.
- Таблица длин пакетов генерируется скриптом из `uAthena/db/packet_db.txt` и хранится в репозитории как исходник.
- Результат: `dinput.dll`, `uaro-pad.ini` и короткий `README.ru.md` (установка и удаление).

## 12. Риски

| Риск | Что делаем |
|---|---|
| Клиент читает мышь не так, как ожидается | Диагностика M0 до основной работы; запасные механизмы в разделе 7 |
| В точке ходьбы актор или окно интерфейса | Варианты (а)–(в) из раздела 7, решение в M1 |
| Клиент «не знает» о действиях, отправленных пакетами, и путается в своём состоянии | Анимации приходят от сервера; если найдутся побочные эффекты — разбираем по случаю |
| Антивирус ругается на DLL с перехватом функций | Для себя — исключение в антивирусе; для раздачи игрокам — подпись кода (позже) |
| Защита сервера от флуда | Ограничения темпа (раздел 9) |

## 13. Вне рамок v1

Камера и курсор на правом стике; меню, диалоги НПЦ и экранная клавиатура; баффы и лечение на других игроков;
подсказки в чате и маркер над целью; настройка раскладки без ini; раздача игрокам через патчер.
